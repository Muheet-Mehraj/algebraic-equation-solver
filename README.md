# Algebraic Equation Store & Solver

Spring Boot (Java 21) REST service that stores algebraic equations as **postfix expression trees**,
lists them back as readable infix text, and evaluates them for given variable values.
Storage is in-memory (as the assignment specifies), so data resets on restart.

* Swagger UI: `http://localhost:8080/swagger-ui.html`
* OpenAPI JSON: `http://localhost:8080/v3/api-docs`

## Run

Requires JDK 21 and Maven 3.9+.

```bash
mvn spring-boot:run            # start on :8080 (override with PORT=9090)
mvn test                       # run all tests (JaCoCo report: target/site/jacoco/index.html)
mvn package && java -jar target/equation-solver-1.0.0.jar
```

Docker: `docker build -t equation-solver . && docker run -p 8080:8080 equation-solver`

## API

| Method | URL | Purpose |
|---|---|---|
| POST | `/api/equations/store` | Parse, validate and store an equation (201) |
| GET | `/api/equations` | List equations, reconstructed from their trees |
| GET | `/api/equations/{id}` | One equation (extra, used for the `Location` header) |
| POST | `/api/equations/{id}/evaluate` | Evaluate with variable values |

```bash
curl -X POST localhost:8080/api/equations/store -H 'Content-Type: application/json' \
     -d '{"equation": "3x + 2y - z"}'
# 201 {"message":"Equation stored successfully","equationId":"1","postfix":"3 x * 2 y * + z -"}

curl localhost:8080/api/equations
# {"equations":[{"equationId":"1","equation":"3x + 2y - z","postfix":"3 x * 2 y * + z -"}]}

curl -X POST localhost:8080/api/equations/1/evaluate -H 'Content-Type: application/json' \
     -d '{"variables": {"x": 2, "y": 3, "z": 1}}'
# {"equationId":"1","equation":"3x + 2y - z","variables":{"x":2,"y":3,"z":1},"result":11}
```

> The assignment's sample shows `result: 10` for these inputs, but 3·2 + 2·3 − 1 = **11**; the service returns the mathematically correct value.

`postfix` is an additive field on top of the specified responses.

### Errors

Every failure uses one shape: `{timestamp, status, error, message, path, details[]}`.

| Situation | Status |
|---|---|
| Blank/missing equation, bad syntax, malformed JSON, non-numeric or null variable value, **missing variables** (listed in `details`) | 400 |
| Unknown equation id | 404 |
| Valid but not computable: division by zero, non-finite result (`(-8)^0.5`, `10^400`) | 422 |

## Equation language

* Operators `+ - * / ^`, parentheses, unary minus, decimals (`1.5`, `.5`).
* Implicit multiplication: `3x`, `2(x+1)`, `(a+b)(c+d)`.
* Variables are `[A-Za-z_][A-Za-z0-9_]*`, so **`xy` is one variable**; write `x*y` or `x y` for a product.
* Precedence (high to low): `^` (right-assoc) > unary `-` > `* /` > `+ -`; so `-x^2 = -(x^2)` and `2^3^2 = 512`.
* Max length 500 characters. Extra variables in an evaluate request are ignored.

## Design

```
text ──Tokenizer──▶ tokens ──InfixToPostfixConverter──▶ postfix ──ExpressionTreeBuilder──▶ tree
                                  (shunting-yard + syntax validation)       (operand stack)
```

* `core` has no Spring dependency: `Tokenizer`, `InfixToPostfixConverter`, `ExpressionTreeBuilder`
  (facade: `EquationParser`), sealed node types (`NumberNode`, `VariableNode`, `UnaryNode`, `BinaryNode`).
* **Visitor pattern** for everything done on a tree: `Evaluator`, `InfixPrinter`, `PostfixPrinter`, `VariableCollector`.
* **Strategy via enum**: `Operator` owns precedence, associativity, arity and its arithmetic.
* `repository.EquationRepository` interface with a thread-safe in-memory implementation (swappable for a DB).
* Only the tree is stored; infix/postfix text is regenerated by traversal on read.
* `GlobalExceptionHandler` maps domain exceptions to HTTP errors.

## Tests

* `core/*Test`: tokenizer, precedence/associativity, implicit multiplication, unary minus, syntax errors,
  tree printing and parse→print→parse round trips, evaluation, division by zero, non-finite results, missing variables.
* `service/EquationServiceTest`: store/list/evaluate/not-found, concurrent id uniqueness.
* `api/EquationControllerTest`: full HTTP behaviour via MockMvc (status codes and error bodies).

## Deploy (Render, Docker)

`render.yaml` is included (Blueprint deploy), and `.github/workflows/ci.yml` runs `mvn verify` on every push.
Health check: `GET /actuator/health`.

1. Push this folder to a public GitHub repo.
2. Render → New → Web Service → connect the repo → Runtime **Docker** (it detects the `Dockerfile`); free plan is fine.
3. The app binds to Render's `PORT` automatically. Live Swagger UI is at `https://<service>.onrender.com/swagger-ui.html`.
   (Free instances sleep when idle; open the URL once before recording or submitting.)
